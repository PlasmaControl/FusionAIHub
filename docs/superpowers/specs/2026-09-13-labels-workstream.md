# Labels workstream — curated label tables and rule labels from `data/labels/`

_Design, 2026-09-13 (controller, from the read-only proposal `.superpowers/sdd/labels-workstream-proposal.md`; awaiting the user's review — decisions below are the controller's defaults, each reversible)._

## Why
The user's label inventory `data/labels/Recommender System - Discrete Labels.csv` (38 rows, Priority 5 = highest, 15 rows) and the first curated database `data/labels/resistive_wall_mode/rwm_onsets_{2017,2024}.csv` (56 onsets, 33 shots) define what labels to build next. Rule: **label DATA lives under `data/labels/`, never under `src/`**; code that reads it lives in `src/labelmaker`.

## Measured facts that shape it
- RWM tables: 33 shots in 156785–176092 — **0 in the corpus (185601–204999), 0 in `recommender_v1`, 0 in the features store.** The loader still lands first: it is the contract every later curated list (WPQH, ELM manual labels, disruption) arrives through; a run over the 500 must write zero rows and say so, not fail.
- `qmin` in the features store: 500/500 shots (`resolver=fdp`, `\efit01::top.results.aeqdsk:qmin`, 20 ms). Naive `qmin > 0.95` fires on 99.4 % of the 500; gated to the Ip flat-top (|Ip| > 0.9·max) with ≥ 500 ms exclusive bands it yields hybrid 271 / elevated 60 / high 50 shots.
- `database` is outside `DIAGNOSTIC_EVIDENCE` (Lfix `windows.py`), so curated rows can never become window-feature counts; `ideate/labels/join.py::events_union` picks new event rows up for free; the `events/<shot>_sources.parquet` contract is on the fix branch, not yet in main.

## Design
1. **Manifest, not code, per table**: `data/labels/tables.yaml` (`stem, dir, phenomenon (a lexicons.yaml id, validated), kind point|interval, shot_col, t_col|t0_col/t1_col, t_units ms|s, attr_cols, attr_types, provenance`). `data/labels/README.md` explains the convention and how to add a table.
2. **Loader** `src/labelmaker/events/databases.py`: `TableSpec`, `load_manifest`, `read_table` (times converted to seconds on load, never on disk), `shots`, `events_for_shot(shot) -> (events, source_records)`. Each event: `source="database:<stem>"`, `evidence_kind="database"`, phenomenon from the manifest, point event `t0_s=t1_s=onset/1000`, `attrs` = extra columns verbatim + `table`, `confidence=NaN` (a curated list has no calibrated probability), `diag=""`, `channel=-1`, **`t_cov0_s=t_cov1_s=NaN`** — a listing is not a coverage claim; an absent shot is never a negative. `event_id` keeps the schema's `{shot}-{source}-{n:05d}` form (colon kept; pinned by a test).
3. **Pipeline**: one guarded step in the events stage, same shape as the others. A table that does not list the shot writes **no event row and no source row** (nobody looked); a table that does writes a source row `status=ok, n_events=n, coverage NaN, reason="curated list; coverage unknown"`. Standalone `run.py events --databases-only` ingests a table over any shot list in seconds without the corpus or the GPU path.
4. **ideate**: `labels join` carries the rows through `events_union`; `get_events` shows them in a fourth list `database_intervals` with `coverage: null`, separate from `events` / `text_mentions` / `forecasts`; the phenomena registry's `database` field points at the stems.
5. **Rule labels** from data we already hold: **High q-min** (`d3d_qmin_regime_rule`: hybrid > 0.95 / elevated > 1.5 / high > 2 over ≥ 500 ms exclusive bands inside the Ip flat-top; EFIT01 now, higher-fidelity later through the canonical-feature `sources` list) — this task also wires the features store into the events stage, which un-skips `nbi_counter` and `qh_proxy` (dead today because `ip` is not a corpus group) and absorbs the iteration-1 task **L-Ip**. **Actuator regimes**: `actuator_intervals` gains `regime` in `attrs` and banded phenomena with **fixed physical bins** (NBI 0.5 / 3 / 7 MW; ECH, gas, RMP bins from a census in the task), not population tertiles (measured NBI tertiles of the 500: 3.8 / 6.3 MW).
6. **Roadmap** `docs/LABELS.md` generated by `scripts/labelmaker/labels_roadmap.py` from the CSV + what labelmaker can produce; the CSV stays the user's editable source of truth.

## Tasks (one agent, a few hours each; exit criteria in the proposal §3)
L-D1 loader + RWM (first) → L-D2 q-min rule + features-store wiring (absorbs L-Ip) → L-D3 actuator regimes → L-D7 roadmap → L-D4 fdp probe (Helicon, Pellet, EFC, Current Saturation; probe before any label) → L-D5 L/H-mode intervals → L-D6 `ip_quench` + `locked_mode` (iteration 2).
