# Labels workstream — curated label tables and rule labels from `data/labels/`

_Design, 2026-09-13 (controller, from the read-only proposal `.superpowers/sdd/labels-workstream-proposal.md`; awaiting the user's review — decisions below are the controller's defaults, each reversible)._

## Why
The user's label inventory `data/labels/discrete_labels.csv` (38 rows, Priority 5 = highest, 15 rows) and the first curated database `data/labels/resistive_wall_mode/rwm_onsets_{2017,2024}.csv` (56 onsets, 33 shots) define what labels to build next. Rule: **label DATA lives under `data/labels/`, never under `src/`**; code that reads it lives in `src/labelmaker`.

## Measured facts that shape it
- RWM tables: 33 shots in 156785–176092 — **0 in the corpus (185601–204999), 0 in `recommender_v1`, 0 in the features store.** The loader still lands first: it is the contract every later curated list (WPQH, ELM manual labels, disruption) arrives through; a run over the 500 must write zero rows and say so, not fail.
- `qmin` in the features store: 500/500 shots (`resolver=fdp`, `\efit01::top.results.aeqdsk:qmin`, 20 ms). Naive `qmin > 0.95` fires on 99.4 % of the 500; gated to the Ip flat-top (|Ip| > 0.9·max) with ≥ 500 ms exclusive bands it yields hybrid 271 / elevated 60 / high 50 shots.
- `database` is outside `DIAGNOSTIC_EVIDENCE` (Lfix `windows.py`), so curated rows can never become window-feature counts; `ideate/labels/join.py::events_union` picks new event rows up for free; the `events/<shot>_sources.parquet` contract is on the fix branch, not yet in main.

## Design
1. **Manifest, not code, per table**: `data/labels/tables.yaml` (`stem, dir, phenomenon (a lexicons.yaml id, validated), kind point|interval, shot_col, t_col|t0_col/t1_col, t_units ms|s, attr_cols, attr_types, provenance`). `data/labels/README.md` explains the convention and how to add a table.
2. **Loader** `src/labelmaker/events/databases.py`: `TableSpec`, `load_manifest`, `read_table` (times converted to seconds on load, never on disk), `shots`, `events_for_shot(shot) -> (events, source_records)`. Each event: `source="database:<stem>"`, `evidence_kind="database"`, phenomenon from the manifest, point event `t0_s=t1_s=onset/1000`, `attrs` = extra columns verbatim + `table`, `confidence=NaN` (a curated list has no calibrated probability), `diag=""`, `channel=-1`, **`t_cov0_s=t_cov1_s=NaN`** — a listing is not a coverage claim; an absent shot is never a negative. `event_id` keeps the schema's `{shot}-{source}-{n:05d}` form (colon kept; pinned by a test).
3. **Pipeline**: one guarded step in the events stage, same shape as the others. A table that does not list the shot writes **no event row and no source row** (nobody looked); a table that does writes a source row `status=ok, n_events=n, coverage NaN, reason="curated list; coverage unknown"`. Standalone `run.py events --databases-only` ingests a table over any shot list in seconds without the corpus or the GPU path.
4. **ideate**: `labels join` carries the rows through `events_union`; `get_events` shows them in a fourth list `database_intervals` with `coverage: null`, separate from `events` / `text_mentions` / `forecasts`; the phenomena registry's `database` field points at the stems.
5. **Rule labels** from data we already hold: **High q-min** (`d3d_qmin_regime_rule`: hybrid > 0.95 / elevated > 1.5 / high > 2 over ≥ 500 ms exclusive bands inside the Ip flat-top; EFIT01 now, higher-fidelity later through the canonical-feature `sources` list) — this task also wires the features store into the events stage, which un-skips `nbi_counter` and `qh_proxy` (dead today because `ip` is not a corpus group) and absorbs the iteration-1 task **L-Ip**. **Actuator regimes**: `actuator_intervals` gains `regime` in `attrs` and banded phenomena with **fixed physical bins** (NBI 0.5 / 3 / 7 MW; ECH, gas, RMP bins from a census in the task), not population tertiles (measured NBI tertiles of the 500: 3.8 / 6.3 MW).
6. **Roadmap** `docs/LABELS.md` generated by `scripts/labelmaker/labels_roadmap.py` from the CSV + what labelmaker can produce; the CSV stays the user's editable source of truth.

## The labels workstream is ONE project (user directive, 2026-09-13 evening)
Every row of `data/labels/discrete_labels.csv` is in scope; the CSV is the single source of truth for scope and status. Rows are not categorised by whether work predates the CSV. `docs/LABELS.md` is GENERATED from the CSV plus the labelmaker registry and shows, per row, exactly one status — `done`, `in_progress`, `blocked_external`, `no_data_in_corpus`, `not_started` — plus the evidence (commit, test, shot counts) that justifies it.

**A row is `done` only when all of these hold:** a labelmaker source produces events or labels for it on the 500-shot `recommender_v1` set; the events carry the right `evidence_kind` (detector / heuristic / forecast / text / database — forecasts never count as observed); per-source coverage is written to the sources contract; the phenomenon id is in `lexicons.yaml` and `phenomena.yaml`; ideate's phenomenon search and `get_events` return it; a test guards each of those; and the shot-level count on the 500 is recorded in the ledger.
Pre-existing pieces (tearing model, AE model, transient detector + ELM clock, sawtooth heuristic, `actuator_intervals`, `dalpha_lh`, `qh_proxy`) are not `done` until assessed against the row's Proposed Method and Notes and either marked done with evidence or split into follow-up tasks. Label data lives under `data/labels/`, never `src/`. Curated tables never imply negatives (NaN coverage). Rows depending on colleagues' data (WPQH, manual ELMs, detachment algorithms, disruption, RWM extension, VDE) are `blocked_external` with the named dependency; no placeholders.

## Task groups (one agent each, reviewed and merged before the next dependent one)
- **A. Assess the pre-existing rows** (Tearing, AE, ELM, Sawtooth): what each piece produces today on the 500 (observed vs forecast, shot counts), whether it satisfies the row's Proposed Method, the gap. Tearing: survival/detection models are forecasts — decide whether an observed tearing-onset event (TokEye track + n=1/2 Mirnov criteria) is in scope and specify it. AE: state the existing model's quality (AUROC 0.62 vs humans) and define the TokEye-based observed AE event. ELM: publish an `elm` point-event family from the ELM clock's own peaks (observed ELM, distinct from the class-agnostic transient). Sawtooth: validate the ECE inversion heuristic on ≥ 10 shots against the "0.3–0.6 inversion layer" note; document the ELM-triggered case. Output: a status per row with evidence + follow-up tasks with exit criteria.
- **B. Finish the started rows**: L-D2 High Q-Min (271 / 60 / 50 on the 500; EFIT01 now, higher fidelity later); RWM = `no_data_in_corpus` with the loader as the delivered contract + the request to the table's author for post-2018 shots.
- **C. Actuation rows as one family**: extend `actuator_intervals` so every actuator row has on/off intervals and a `regime` attribute with fixed physical bins (NBI 0.5 / 3 / 7 MW; ECH, gas, RMP bins from a census on the 500). NBI, Gas, RMP, ECH from corpus groups; Helicon, Pellet, EFC, Current Saturation, LH (lower hybrid) via an fdp PROBE first — pointname, units, time base, availability on a 20-shot sample — before any label; nothing in the corpus years → `no_data_in_corpus`. Default readings to confirm: LH = lower-hybrid current drive; Current Saturation = ohmic coil at its current limit.
- **D. Regime rows**: L-Mode / H-Mode intervals from `dalpha_lh` with an explicit `unknown` where no transition is found; QH-Mode via the existing proxy (EHO ∧ ELM-free ∧ NBI ∧ flat-top), marked as a proxy; WPQH `blocked_external`.
- **E. Remaining detector rows**: Pickup, EHO, QCM, Fishbone from the TokEye track descriptors (priors exist); Locked Mode and ip-quench (never "disruption") from `ip` and `n1rms`; Detachment, MARFE, VDE `blocked_external` or `not_started` with the stated reason.
- **F. `docs/LABELS.md` generator** (`scripts/labelmaker/labels_roadmap.py`) reading the CSV and the labelmaker registry, filling status and evidence automatically; regenerated and committed at the end of every task above.
Order: A ∥ C's fdp probe → B → D → E (F alongside). Process: implementation on Codex gpt-6-astra (write mode) by default, opus for easy tasks; TDD; both suites green with `-W error`; ledger entry after every task; no new files under `/scratch/gpfs/nc1514` except repo source; every SLURM job gated with `labelmaker.jobstats`.

## Decisions on the proposal's open questions (defaults; the user may overrule)

2. "Current Saturation" = ohmic (E-coil) current at its limit / flux exhaustion → L-D4 probe first; **needs the user's confirmation**.
3. A database never implies a negative. An optional `examined_range:` manifest field is designed but not built until a table documents its examination scope.
4. RWM: land the loader on the existing tables (contract exercise); ask the user whether to request a post-2018 extension from the table's author; no backward corpus extension.
5. q-min from EFIT01 now; EFIT02/CAKE as a later substitution.
6. Fixed physical bins for actuator regimes.
7. Emails to colleagues (WPQH table, manual ELM labels, detachment, disruption, RWM method, VDE) are the user's, out of agent scope; the roadmap marks those rows "gated on external data".
8. `source="database:<stem>"`, `event_id` with the colon, pinned by a test.
