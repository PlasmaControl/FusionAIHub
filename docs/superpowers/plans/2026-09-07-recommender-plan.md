# recommender: ideate + labelmaker v2 — phenomenon search, event labels, experiment design

_Final plan, 2026-09-07. Synthesised from exploration (3 Explore agents), two Opus Plan agents (labelmaker v2; ideate), and a Codex gpt-6-astra/max design partner whose critique and counter-plan are addressed in §12. Appendices A–C carry the detailed sub-plans the execution agents need._

## 1. Context

Fusion scientists cannot search DIII-D shots by phenomenon, see where a phenomenon occurred, or ask what actuator circumstances preceded it, without days of log reading and plotting. Four disconnected pieces exist: **labelmaker** (`src/labelmaker`, model-based per-time labels, no text, no events), **shot-recommender-system** (`/scratch/gpfs/nc1514/shot-recommender-system`, pkg `shotrec`: text+scalar+IGNITE-codec retrieval, keyword-only phenomena, FastAPI SPA), **TokEye** (class-agnostic coherent/transient spectrogram segmenter), and the **IGNITE** world model (881M-param MaskGIT dynamics, bundle on stellar, never used for design). Smith et al. 2026 (`.tmp/20423_260902_smith_A1.pdf`) built a DIII-D twin around vPCS + Grad–Shafranov + Omniverse + an LLM→TokSearch/MCP interface. Our differentiators: **phenomenon labels/events as first-class relational evidence tying operator text ↔ diagnostics ↔ actuators**, **IGNITE as the what-if engine**, and a **tool-first** system (Python/CLI/HTTP/MCP) any LLM can drive.

Outcome: a scientist (or Claude Code via MCP) types "edge harmonic oscillation" and gets shots ranked by evidence, the exact time/frequency intervals, the operator's own words, the actuator state before/during, a matched comparison of what differed before events vs non-events, and — once qualified — an IGNITE rollout of a proposed actuator program with predicted phenomena and honest caveats.

## 4. Architecture

```
corpus <shot>_processed.h5 ─┬─► labelmaker v2 ──► labels/<shot>_labels.h5 (per-time p, existing)
fdp/archive EFIT ───────────┤   ├ existing adapters (tearing, ELM, AE)      events/<shot>_events.parquet  ─┐
TokEye U-Net (vendored) ────┤   ├ events/: masks → tracks → descriptors      masks/<shot>_masks.npz         │
text per_shot_txt ──────────┘   ├ heuristics: sawtooth, L-H, ELM clock, actuator intervals, QH proxy        │
                                ├ text_weak: per-shot lexicon hits (never a label alone)                   │
                                └ annotate/: candidates → render NNNN.png + sheet.csv → train GBDT → infer  │
                                                                                                           ▼
                                                        ideate DB ($IDEATE_DATA_ROOT/db: parquet + npy, DuckDB view)
                                                        shots · coverage · segments · windows · events · labels_wide · text · phenomena
                                                                     │
                                          search ─ locate ─ describe ─ circumstances ─ suggest ─ design
                                                                     │
                                            Python API · CLI · MCP (stdio) · FastAPI SPA (it.2)
                                                                     │
IGNITE bundle (codecs + dynamics) ───► design/: encode ref shot → edit actuators (ref stats) → rollout → decode → spectral bridge → predicted phenomena + caveats
```

Ownership: **labelmaker** owns diagnostic transforms, masks, events, heuristics, annotation import, classifier training/inference, label quality. **ideate** owns the relational DB, text claims, search/ranking, circumstances, proposals, interfaces, IGNITE design loop. ideate never writes into `$LABELMAKER_ROOT`.

## 5. Data contracts

### 5.1 `events/<shot>_events.parquet` (owner: labelmaker; unified schema)
`shot int32 · event_id str ("{shot}-{source}-{n:05d}") · source str · evidence_kind str {detector, heuristic, forecast, text, human, database, model} · phenomenon str · t0_s, t1_s float64 (half-open; point event t1==t0) · f0_khz, f1_khz float32 (NaN if none) · confidence float32 · horizon_s float32 (NaN unless forecast) · diag str · channel int16 (−1 derived) · pass_name str {wide, zoom, ""} · attrs str (JSON descriptor block) · t_cov0_s, t_cov1_s float64 · run_id, git_sha, written_at str`.
Sources: `tokeye_track, tokeye_transient, ece_sawtooth, dalpha_lh, elm_clock, actuator, qh_proxy, text, model, label_forecast (ideate-derived from DSM risks), database`. `events_index.parquet` per (shot, source, phenomenon) via `labels.store.append_index(keys=[...])`.

### 5.2 `masks/<shot>_masks.npz` (one file per shot)
Per `(diag, ch, pass)` prefix: `_coh_packed`, `_tra_packed` uint8 packbits (thr 0.2), `_row_lit (512,)`, `_col_act (T,)`, `_band_logpow float16 (16,T)`, `_t_s (T,)`, `_meta` JSON (fs, decim, n_cols, spec_mean/std, clip, tile, overlap, unet_sha256). Optional `masks/probs/…npz` uint8 probabilities only for rendered windows.

### 5.3 Annotation folder `$LABELMAKER_ROOT/annotate/<phenomenon>/`
`chunks/NNNN.png`, `sheet.csv` (header exactly `file,shot,t0_s,t1_s,phenomenon,label,notes`; `label ∈ {y,n,?,""}`), `manifest.parquet` (adds `is_negative, prior_score, why, seed, diags`; **is_negative not in the sheet**; numbering is a seeded shuffle), `features.parquet` (46-dim window features), `README.md`. `sheet.read_sheet` refuses a sheet whose keys mismatch the manifest.

### 5.4 Trained classifier folder `models/d3d_<phen>_activity_gbdt/`
`gbdt.npz` (flat tree arrays + isotonic knots) + HF card + `spec.py` (`framework="gbdt_npz"`, `InputField("window_features","phenomenon_window_features")`, output `<phen>_prob` binary, activation none, `training_shots`). Runner `models/runners/gbdt_npz.py` (numpy only). Rule-based `d3d_sawtooth_activity_rule`, `d3d_lh_transition_rule` (artifacts=(), `heuristic: true`).

### 5.5 ideate DB (`$IDEATE_DATA_ROOT/db/`)
`shots.parquet` (shotrec SHOT_COLS + `has_*` flags, `groups_filled`, `feature_resolvers`, `has_frame_codes`), `corpus_coverage.parquet` (shot, group, n_channels, n_samples, t0_s, t1_s, fs_hz, openable — the fresh census), `segments.parquet`, `windows.parquet`, `events.parquet` (union of labelmaker events + ideate-derived `label_forecast`/`actuator`/`text`), `labels_wide.parquet` (shot, slug, label, n_valid, valid_frac, max/mean/p95_valid, thr, thr_source {card,config,""}, frac_above, first_above_t_s, n_intervals, longest_interval_s, artifact_sha256), `text.parquet`, `phenomena.parquet` (text hits), `text_claims.parquet` (shot, phenomenon, polarity {pos,neg,uncertain}, temporality {observed,planned,historical}, snippet — from shotrec `text.py` verdict/negation logic), embeddings `emb_scalar/emb_text_mp/emb_text_log/emb_ignite_seg/emb_ignite_win.npy`, `manifest.json`. DuckDB is a read-only query convenience over these parquets (optional dependency), not a second store.

### 5.7 `recommender_v1` selection rule (500 shots, `ideate corpus select`)
Pool: corpus ∩ text (13,313). Each candidate must satisfy **all**: (a) `SHOT TABLE ROW` `SHOT_TYPE == plasma`, `IP-(MA) ≥ 0.5`, `PULSE-LENGTH ≥ 2 s`, and (`PBEAM-MAX ≥ 1 MW` or `PECH-MAX > 0`); (b) shot-specific text block ≥ 300 chars and not the session-fallback case; title not matching test/PS/Bcoil/abort/"Mag Cal"; (c) corpus groups `mhr ∧ ece ∧ filterscopes` present (fresh census, `shape[-1] ≥ 2`) with ≥ 2 s coverage each; (d) Ip flat-top ≥ 1 s. Diversity: ≤ 3 shots per `run_id`, ≤ 5 per `mpid`; theme quotas from the 14 lexicon themes (≥ 20 per theme where available; `startup_checkout` excluded); spread across 2020–2025; ≥ 50 shots with `co2`, ≥ 50 with `bes`, ≥ 30 with `tangtv`; prefer the labelmaker-featured shots (526) and the 10 IGNITE `frame_codes` shots when they qualify (features/codes already exist) but cap them at 150 so they do not dominate. EFIT scalars: archive where available, else fdp (Q2; if fdp is disallowed, restrict the pool to corpus ∩ archive ∩ text = 2,654). Output `configs/ideate/shot_lists/recommender_v1.yaml` with per-shot `theme`, `reason`, `year`, `has_co2/bes/tangtv`, plus a `hand_review: {drop: [], add: []}` block; the same list is `$LABELMAKER_ROOT/recommender_v1.txt` for the mask job.

### 5.6 `configs/ideate/phenomena.yaml`
Per phenomenon: `title, aliases, exclude, labels [{slug,label,thr,weight}], events [sources], band_khz, diags, requires_group, prior, database`. Round-1 ids: `ae, eho, elm, tearing, sawtooth, fishbone, qcm, qh, lh, detachment, pickup, rwm`. `labelmaker/events/lexicons.yaml` mirrors the alias lists (single source: ideate reads labelmaker's lexicon file).

## 7. Workstream I — ideate (detail in Appendix B)

Port map: `shotrec` → `src/ideate/` keeping `schema, config, cli, shotdb/, retrieval/, flags/, llm/, ui/`; drop `fetch`/`curate`/`to_processed_h5`/`pcslayout`; keep `rawfile.py` as optional `legacy_raw` source; new `shotdb/reader.py` (`Reader` protocol) + `shotdb/corpus.py::CorpusReader` (xdata seconds→ms, `(C,1)` sentinel, `OSError` → shot failed); `labels/join.py`; `retrieval/phenomena.py` (`registry/resolve/evidence/locate`, `PhenomenonHit` with `intervals`, `caveats`), `retrieval/circumstances.py`; `design/{actuators,seed,rollout,decode,spectra,predict,report}.py`; `mcp/server.py` (mcp 2.x `MCPServer`, tools: `search_shots, phenomenon_locate, describe_shot, get_events, circumstances, suggest_configuration, check_proposal, design_rollout, get_job`; `ui/chat.py::TOOLS` generated from the MCP registry); `eval/{prompts,phenomenon_recall,latency}.py`; `configs/ideate/*.yaml`; `tests/ideate/` (~560 ported + new, `-W error`).

`ShotDB.mask` gains precomputed per-segment token sets (`phenomenon:<id>`, `label:<slug>/<name>`, `source:<kind>`) so `require_labels/avoid_labels` work with ~15 lines; `avoid` requires observable coverage (a shot with no data is not a negative). New channel `CHANNELS["phenomenon"]` (score = w_label·max p + w_event·sat(n_events) + w_text·tanh(hits/2) + w_database), weight 1.2, returns `[]` when no phenomenon resolves so RRF is unaffected. Observed evidence ranks above forecasts; forecasts shown in a separate field.

Circumstances (`retrieval/circumstances.py`): unit = pre-event window `[t0−lead−w, t0−lead)` (lead 50 ms, w 300 ms); features = window means + slopes + Δ from the shot's flat-top baseline for registry signals and labelmaker scalars; **two arms**: within-shot (windows ≥2w away from any event) and between-shot (1:3 propensity-matched on ip, bt, betan, kappa, tri, pnbi, campaign, caliper 0.25 SD; unmatched reported); stats per feature: Hedges g, AUROC, **shot-clustered bootstrap CI** (B=1000), shot-level permutation p → BH q; rank by |g| among q≤0.1 and n_event_shots≥5, others listed as underpowered; `correlated_with` field; run_id stratum; descriptive-only below 30 independent case shots; mandatory caveat text ("observational, not causal"). Diagnostic classifiers exclude actuator/scalar context features when their labels feed circumstances (no circularity); context-enhanced variants carry feature lineage.

Design (`design/`): `ACT_SPEC` 88 channels (V9); `frame_means/z_score/apply(policy="reference_stats")`; `encode_frame_codes(shot)` = shotrec `frame_codes` (14 modalities incl. tangtv codecs) + actuators → `$IDEATE_DATA_ROOT/frame_codes/<shot>.pt`; **G-ENC**: reproduce shipped `frame_codes/190090.pt` bit-identically (codes) and within fp16 tolerance on ≥82/88 actuator channels, repeat on 202537, 204346; `rollout.py` ported from `ignite_infer.py` onto sibling `tokamak_foundation_model.ignite` (validate_shot on); `decode.py` + `spectra.py` (`unstandardize`, `to_ae_input`, TokEye-transform bridge); **G-DEC**: AUROC of AE-from-decoded-GT-tokens vs AE-from-raw on ≥5 co2 shots ≥ 0.8 else claim dropped; `DesignReport` always includes `nearest_real_shots`, token divergence AND decoded band-restricted change, per-modality skill vs persistence, `frac_static`, extrapolation warnings; only reconstructible label models run (AE via bridge, TokEye tracks on decoded spectrograms, ELM DSM low-confidence; tearing/EFIT models "not predictable"). Rollouts are async jobs (`JobHandle`), 1 s horizon interactive on login V100S, 4 s on A100 (4 concurrent per 40 GB).

## 12. Critique of the Codex partner's counter-plan (what was adopted / rejected)
**Adopted:** evaluation-first sequencing folded into iteration 0 (fresh census, frozen splits, quality of existing labels stated); forecast ≠ observed event (`evidence_kind`, `horizon_s`); "no assertion ≠ absent label" (`avoid` requires coverage); text claims with polarity/temporality via shotrec's existing negation/mitigation parser; blind rendering and hard negatives; exclusion of actuator context from diagnostic classifiers to avoid circular circumstances; run-day stratification and the 30-shot descriptive-only threshold; storage of compact masks; utilization honesty (pilot-sized requests, raw jobstats preserved, GPU-memory occupancy not read as work); IGNITE gates B–D (as G-DEC + skill/frac_static reporting + reference-stats edits) and gate E deferred; MCP framed as access, the phenomenon DB as the differentiator; rubric caps.
**Rejected or narrowed:** (1) its 20-table relational model with enums/FKs and a DuckDB catalog as the store — over-engineered for parquet-backed research tooling; we keep ~9 parquet tables and DuckDB as an optional read-only query layer. (2) "88-channel contract unresolved / Gate A blocks design" — Plan B measured the layout against shipped frame codes (V9); Gate A becomes the G-ENC test in iteration 0, not an external handoff dependency (the handoff remains desirable for provenance). (3) "one phenomenon only (EHO)" — the loop is generic and rendering is cheap; sheets for all 7 are produced, annotation is prioritised EHO → sawtooth → L-H, and a classifier is trained only where the sheet meets the ≥60/≥15 threshold. (4) Seven iterations with a separate "truth" iteration — merged into five; usefulness must appear by iteration 1, not iteration 3. (5) Its insistence that TokEye tiling equivalence be proven — adopted as a test (constant map identity, overlap averaging) rather than a gate.
