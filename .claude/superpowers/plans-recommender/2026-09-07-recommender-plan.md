# recommender: ideate + labelmaker v2 — phenomenon search, event labels, experiment design

_Final plan, 2026-09-07. Synthesised from exploration (3 Explore agents), two Opus Plan agents (labelmaker v2; ideate), and a Codex gpt-6-astra/max design partner whose critique and counter-plan are addressed in §12. Appendices A–C carry the detailed sub-plans the execution agents need._

## 1. Context

Fusion scientists cannot search DIII-D shots by phenomenon, see where a phenomenon occurred, or ask what actuator circumstances preceded it, without days of log reading and plotting. Four disconnected pieces exist: **labelmaker** (`src/labelmaker`, model-based per-time labels, no text, no events), **shot-recommender-system** (`/scratch/gpfs/nc1514/shot-recommender-system`, pkg `shotrec`: text+scalar+IGNITE-codec retrieval, keyword-only phenomena, FastAPI SPA), **TokEye** (class-agnostic coherent/transient spectrogram segmenter), and the **IGNITE** world model (881M-param MaskGIT dynamics, bundle on stellar, never used for design). Smith et al. 2026 (`.tmp/20423_260902_smith_A1.pdf`) built a DIII-D twin around vPCS + Grad–Shafranov + Omniverse + an LLM→TokSearch/MCP interface. Our differentiators: **phenomenon labels/events as first-class relational evidence tying operator text ↔ diagnostics ↔ actuators**, **IGNITE as the what-if engine**, and a **tool-first** system (Python/CLI/HTTP/MCP) any LLM can drive.

Outcome: a scientist (or Claude Code via MCP) types "edge harmonic oscillation" and gets shots ranked by evidence, the exact time/frequency intervals, the operator's own words, the actuator state before/during, a matched comparison of what differed before events vs non-events, and — once qualified — an IGNITE rollout of a proposed actuator program with predicted phenomena and honest caveats.

## 4. Architecture

```
corpus <shot>_processed.h5 ─┬─► labelmaker v2 ──► labels/<shot>_labels.h5 (per-time p, existing)
fdp/archive EFIT ───────────┤   ├ existing adapters (tearing, ELM, AE)      events/<shot>_events.parquet  ─┐
TokEye U-Net (vendored) ────┤   ├ events/: masks → tracks → descriptors      masks/<shot>_masks.npz         │
text logs.jsonl+per_shot_txt┘   ├ heuristics: sawtooth, L-H, ELM clock, actuator intervals, QH proxy        │
                                ├ text_weak: per-shot lexicon hits (never a label alone)                   │
                                └ annotate/: candidates → render NNNN.png + sheet.csv → train GBDT → infer  │
                                                                                                           ▼
                                                        ideate DB ($IDEATE_DATA_ROOT/db: parquet + npy, DuckDB view)
                                                        shots · coverage · segments · windows · events · labels_wide · text · phenomena
                                                                     │
                                          search ─ locate ─ describe ─ circumstances ─ suggest ─ design
                                                                     │
                                            Python API · CLI · MCP (stdio) · FastAPI SPA (it.2)
                                                                     │
IGNITE bundle (codecs + dynamics) ───► design/: encode ref shot → edit actuators (ref stats) → rollout → decode → spectral bridge → predicted phenomena + caveats
```

**Two distinct text sources** [amended 2026-09-07 post-critic: the diagram named only `per_shot_txt`; measured in L7/L7-fix]: **shot scope** = `sql/logs.jsonl` (53,179 records, one per shot; the shot's own logbook entries, median 1,270 chars over 5 entries; the PCS parameter dump excluded), cached per run as `$LABELMAKER_ROOT/text/logs_subset.jsonl` with a `.missing` sidecar; **run context** = `per_shot_txt/shot_<N>.txt`, whose block after the `## Shot-specific context` marker is ONLY the `SHOT TABLE ROW` (≤ 379 bytes, no prose) — every phenomenon word in that file lives in run-scope session text. `text_weak` reports the two scopes separately, and a run-scope hit is never shot-scope evidence.

Ownership: **labelmaker** owns diagnostic transforms, masks, events, heuristics, annotation import, classifier training/inference, label quality. **ideate** owns the relational DB, text claims, search/ranking, circumstances, proposals, interfaces, IGNITE design loop. ideate never writes into `$LABELMAKER_ROOT`.

## 5. Data contracts

### 5.1 `events/<shot>_events.parquet` (owner: labelmaker; unified schema)
`shot int32 · event_id str ("{shot}-{source}-{n:05d}") · source str · evidence_kind str {detector, heuristic, forecast, text, human, database, model} · phenomenon str · t0_s, t1_s float64 (half-open; point event t1==t0) · f0_khz, f1_khz float32 (NaN if none) · confidence float32 · horizon_s float32 (NaN unless forecast) · diag str · channel int16 (−1 derived) · pass_name str {wide, zoom, ""} · attrs str (JSON descriptor block) · t_cov0_s, t_cov1_s float64 · run_id, git_sha, written_at str`.
Sources: `tokeye_track, tokeye_transient, ece_sawtooth, dalpha_lh, elm_clock, actuator, qh_proxy, text, model, label_forecast (ideate-derived from DSM risks), database`. `events_index.parquet` per (shot, source, phenomenon) via `labels.store.append_index(keys=[...])`.

**`events/<shot>_sources.parquet` — source completion / coverage table** [added 2026-09-07 post-critic, task Lfix-C1; critic defect 2 "coverage truth is lost between detectors, storage, and MCP"]: one row per attempted source (specified here; landed 2026-09-13 with the fix-C1 merges — see the ledger. **Known defect, critic #3 2026-09-14:** the recorded span is the HULL of finite samples, so an interior data gap is published as covered and a window inside it answers `observed`; task C3fix replaces the span by a set of disjoint finite intervals per source) — `shot int32 · source str · status str {ok, skipped, error} · reason str · t_cov0_s, t_cov1_s float64 · n_events int32 · diag str · channel int16 · pass_name str · run_id, git_sha, written_at str` — so "ran and found nothing" is distinguishable from "not processed", and an absent product can never be read as an observed absence. Coverage is recorded **per source on its own axis** (each actuator from its own group's axis, L→H from the intersection of its inputs, finite samples only); the earlier per-shot union gave every actuator event the union of unrelated axes (NBI/RMP on 198658 inherited gas's −10…94.9 s). Track rows are clipped to their coverage span.

**Evidence policy for window features** [added 2026-09-07 post-critic; critic defect 1 "text and forecasts become diagnostic event counts"]: `events/windows.py::EventTable` selects rows by phenomenon **and by `evidence_kind ∈ {detector, heuristic}`**. Text mentions and forecasts must never enter a diagnostic count. Regression cases: the real 185980 note ("updated elm detector tuning", which had become `elm_rate_hz = 2.94`), the 193348 note, and a schema-valid ELM forecast at 1 s.

### 5.2 `masks/<shot>_masks.npz` (one file per shot)
Per `(diag, ch, pass)` prefix: `_coh_packed`, `_tra_packed` uint8 packbits (thr 0.2), `_row_lit (512,)`, `_col_act (T,)`, `_band_logpow float16 (16,T)`, `_t_s (T,)`, `_meta` JSON (fs, decim, n_cols, spec_mean/std, clip, tile, overlap, unet_sha256). Optional `masks/probs/…npz` uint8 probabilities only for rendered windows.

### 5.3 Annotation folder `$LABELMAKER_ROOT/annotate/<phenomenon>/`
`chunks/NNNN.png`, `sheet.csv` (header exactly `file,shot,t0_s,t1_s,phenomenon,label,notes`; `label ∈ {y,n,?,""}`), `manifest.parquet` (adds `is_negative, prior_score, why, seed, diags`; **is_negative not in the sheet**; numbering is a seeded shuffle), `features.parquet` (46-dim window features), `README.md`. `sheet.read_sheet` refuses a sheet whose keys mismatch the manifest.

### 5.4 Trained classifier folder `models/d3d_<phen>_activity_gbdt/`
`gbdt.npz` (flat tree arrays + isotonic knots) + HF card + `spec.py` (`framework="gbdt_npz"`, `InputField("window_features","phenomenon_window_features")`, output `<phen>_prob` binary, activation none, `training_shots`). Runner `models/runners/gbdt_npz.py` (numpy only). Rule-based `d3d_sawtooth_activity_rule`, `d3d_lh_transition_rule` (artifacts=(), `heuristic: true`).

### 5.5 ideate DB (`$IDEATE_DATA_ROOT/db/`)
`shots.parquet` (shotrec SHOT_COLS + `has_*` flags, `groups_filled`, `feature_resolvers`, `has_frame_codes`), `corpus_coverage.parquet` (shot, group, n_channels, n_samples, t0_s, t1_s, fs_hz, openable — the fresh census), `segments.parquet`, `windows.parquet`, `events.parquet` (union of labelmaker events + ideate-derived `label_forecast`/`actuator`/`text`), `event_sources.parquet` (the per-shot source-completion table of §5.1, ingested by `ideate labels join` so an absent product is never served as an observed absence), `labels_wide.parquet` (shot, slug, label, n_valid, valid_frac, max/mean/p95_valid, thr, thr_source {card,config,""}, frac_above, first_above_t_s, n_intervals, longest_interval_s, artifact_sha256), `text.parquet`, `phenomena.parquet` (text hits), `text_claims.parquet` (shot, phenomenon, polarity {pos,neg,uncertain}, temporality {observed,planned,historical}, snippet — from shotrec `text.py` verdict/negation logic), embeddings `emb_scalar/emb_text_mp/emb_text_log/emb_ignite_seg/emb_ignite_win.npy`, `manifest.json`. DuckDB is a read-only query convenience over these parquets (optional dependency), not a second store.

**Processing status, coverage and cache availability** [added 2026-09-07 post-critic; specified here; implemented by task Ifix-C1, landed 2026-09-13 with the fix-C1 merges]: `has_frame_codes` is **refreshed by `ideate labels join` from the frame-code directory on every run** — the committed table read 13/487 true while 500 caches existed. Field coverage is `present | unavailable | pending` and **never 0**: after the login-node fdp fetch, betan/kappa/qmin/li/bt/pcbcoil are present 500/500; ne0/te0 489 present + 11 `unavailable` (TreeNODATA — no zipfit profiles); r0 499 + 1 `unavailable`; `pech_HAN`/`gas_PFX3` unavailable on all 500. Deviations in force: `ne_line` ← co2 ch 2 (V2 chord), `neutrons` ← neutron_rate ch 3. `ideate labels join` must be re-run after **every** rebuild.

### 5.7 `recommender_v1` selection rule (500 generated shots; 504 effective since 2026-09-14 through `hand_review.add`; `ideate corpus select`)

Each candidate must satisfy **all**: (a) `SHOT TABLE ROW` `SHOT_TYPE == plasma`, `abs(IP-(MA)) ≥ 0.5` with the sign preserved as `ip_sign` for interpretation [amended 2026-09-07 post-critic: magnitude test, sign kept; was: signed `IP-(MA) ≥ 0.5`] — the signed test excluded all 663 reversed-current plasma shots (254 QH-titled, on 13 run days) that met the intended magnitude requirement; 40 reversed-Ip shots are in the finalized list, `PULSE-LENGTH ≥ 2 s`, and (`PBEAM-MAX ≥ 1 MW` or `PECH-MAX > 0`); (b) shot-specific **structural** text block ≥ 200 chars and not the session-fallback case [amended 2026-09-07 post-critic: 200 chars, and the block is named structural; was: ≥ 300 chars] — the block after the marker is only the `SHOT TABLE ROW`: all 178 real blocks measure 138–302 chars and the selected ones 221–282, so a 300-char floor admitted none. **This floor measures structural content, not rich shot prose** — shot prose lives in `sql/logs.jsonl` (§4); title not matching test/PS/Bcoil/abort/"Mag Cal"; (c) corpus groups `mhr ∧ ece ∧ filterscopes` present (fresh census, `shape[-1] ≥ 2`) with ≥ 2 s coverage each; (d) Ip flat-top ≥ 1 s.
