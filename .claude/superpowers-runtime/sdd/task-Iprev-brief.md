# Task I-prev — `ideate build` must not clobber a different database; every write names its root; the build times its phases

Worktree: `/scratch/gpfs/nc1514/FusionAIHub-Iprev`, branch `recommender-Iprev` cut from `recommender` @ 3cced76. Package `src/ideate`; docs `docs/IDEATE.md`; tests `tests/ideate` (currently 1176, `-W error`).

## Why (incident 2026-09-14, ledger entry "INCIDENT")
A one-shot scratch `ideate build` was run through `pixi run -e ideate-cpu` with `IDEATE_DATA_ROOT` exported to a /tmp directory. pixi's `[activation.env]` (pyproject.toml, feature `ideate`) sets `IDEATE_DATA_ROOT=/scratch/gpfs/EKOLEMEN/nc1514/ideate` and overrides the caller's value, so `_publish` (`src/ideate/shotdb/build.py`) replaced the production 500-shot database with a 1-shot one. Nothing in `build` looked at what it was about to overwrite, and nothing printed the resolved root before writing. The DB has since been rebuilt (SLURM). Your job is to make that class of accident impossible to do silently — without weakening the atomic-publish design.

## Deliverables (TDD: failing test first for each; keep every existing test green)
1. **Publish guard.** In `build()` before `_publish`: if `<db_dir>/manifest.json` exists, compare the existing manifest's `shot_source` and `n_shots` with the new build's. Refuse — no file touched, non-zero exit, a message naming both sources and both counts and the `--force` flag — when the `shot_source` differs, or when the new `n_shots` is smaller than the existing one (a `--limit` pilot, a `shots:1` build). Same source and ≥ as many shots publishes as today (the 2026-09-14 rebuild went 500 → 504 over `list:recommender_v1` and must still pass). `ideate build --force` overrides and the manifest records `"forced_over": {previous shot_source, n_shots, built_at}`. `ideate add` and `ideate labels join` are upserts and are NOT guarded. A corrupt/unreadable existing manifest counts as "different" (refuse without `--force`).
2. **Every writing CLI command prints its resolved data root and where it came from** on stderr before the first write: `build`, `add`, `labels join`, `encode`, `corpus scan|select` (whichever write under the root). Origin is one of `IDEATE_DATA_ROOT env`, `IDEATE_PATHS=<file>`, `configs/ideate/paths.yaml default` — see `src/ideate/config.py` (`load_paths`, lines ~84–89) and add a small accessor rather than re-deriving it in the CLI. One line, e.g. `ideate build: data root /x/y (IDEATE_DATA_ROOT env) -> db /x/y/db`.
3. **Build phase timing.** `build()` measures wall seconds per phase — reading shot records, segmenting, scalar PCA/embeddings, text embeddings, writing tables, publish — logs them at the end and stores `phase_seconds: {phase: float}` in the manifest. This is for the ledger's open diagnosis: three SLURM builds ran at 65–68 % CPU on 3–6 cores and nobody knows which phase idles the cores. Test on the fixture DB that the keys are exactly the phase list and the values are non-negative floats.
4. **Docs.** A section in `docs/IDEATE.md` — "Scratch databases and the pixi activation env" — stating that `pixi run -e ideate*` pins `IDEATE_DATA_ROOT`, `LABELMAKER_ROOT` and `IDEATE_CORPUS`, so a scratch build must use the env interpreter directly (`/scratch/gpfs/nc1514/FusionAIHub/.pixi/envs/ideate-cpu/bin/python -m ideate …` with the variables exported) or `IDEATE_PATHS=<own paths.yaml>`; that the root line of deliverable 2 is how you check; and what the guard of deliverable 1 refuses. Keep it short and exact.
5. Report `.superpowers/sdd/task-Iprev-report.md` (tracked, in the worktree): what changed, the red→green evidence per deliverable, suite summaries, `git log --oneline recommender..recommender-Iprev`, deviations.
